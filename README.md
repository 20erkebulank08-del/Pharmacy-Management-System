# 💊 CASE 16 · Pharmacy Management System (Дәріхана желісі)

«SQL және деректер қорын басқару» пәніне арналған PostgreSQL 16 оқу жобасы. Базаны pgAdmin 4 немесе `psql` арқылы іске қосуға болады.

## 📌 Сипаттамасы

Бір препарат филиалға әртүрлі партиямен және әртүрлі жарамдылық мерзімімен келуі мүмкін. Жүйе әр сатылған қаптаманы нақты қоймадағы партияға байланыстырады. Осы байланыс арқылы фармацевт сату күні препараттың жарамдылығын тексереді, ал филиал меңгерушісі қай партияны алдымен босату және қай препаратты толықтыру керегін анықтайды.

| Оқу деректері | Көлемі |
|---|---|
| Дәріхана желісі | 10 филиал, 12 қойма, 100 препарат, 750 партия |
| Сату | 150 тіркелген клиент, 450 төленген чек, 1 000 чек жолы |
| Төлем және қайтарым | 500 сәтті төлем, 10 сәтсіз әрекет, 60 қайтарым құжаты |
| Есептік кезең | Сату күндері 2025-11-25 пен 2026-11-24 аралығында. Есептік күн — 2026-11-24. |

## ▶️ pgAdmin 4 арқылы іске қосу

1. PostgreSQL серверіне қосылыңыз. **Databases → Create → Database…** арқылы `pharmacy_case` атты бос деректер қорын жасаңыз.
2. `pharmacy_case` базасын таңдап, **Query Tool** ашыңыз. Файлдардың басындағы кері қиғаш сызықтан басталатын жолдар (`\set`, `\if`, `\connect`) — `psql` командалары. Query Tool ішінде келесі қадамдарда көрсетілген SQL бөлігін ғана белгілеп орындаңыз.
3. **Open File** арқылы `03_database_structure.sql` файлын ашыңыз. Алғашқы `BEGIN;` жолынан соңғы `COMMIT;` жолына дейін белгілеп, **Execute / F5** басыңыз.
4. `04_data_insert.sql` файлын ашыңыз. Мұнда да `BEGIN;` мен `COMMIT;` аралығын екеуін қоса белгілеп, бір рет орындаңыз. Қабылдау мен қорды азайту триггерлері жүктеу кезінде қосулы болуы керек.
5. `05_queries.sql` файлын ашып, мысалы, `-- Q01` астындағы сұранысты соңғы нүктелі үтіріне дейін белгілеңіз. **Execute / F5** басқанда **Data Output** бөлімінде 120 партия шығуы тиіс. `WITH` сөзінен басталатын есепте сұранысты сол сөзден бастап толық белгілеңіз.

Жүктеуді мына сұраныспен тексеруге болады. Күтілетін нәтиже — 450 чек, жалпы сома **2 469 873 ₸**.

```sql
SELECT COUNT(*) AS paid_receipts, SUM(total_amount) AS gross_amount
FROM sales
WHERE status = 'paid';
```

### Терминалдан толық іске қосу

Жоба каталогында төмендегі командаларды орындаңыз. Бірінші команда жаңа база құрады. pgAdmin арқылы базаны дайындап, деректерді енгізген болсаңыз, үшінші командадан бастаңыз.

```sh
psql -X -d postgres -v new_db=pharmacy_case -f 03_database_structure.sql
psql -X -d pharmacy_case -f 04_data_insert.sql
psql -X -d pharmacy_case -f 05_queries.sql
```

## 🗂 Кестелер және байланыстар

Негізгі қозғалыс төменде көрсетілген. `1 ──< M` белгісі бір жазбаға бірнеше жол сілтей алатынын білдіреді. Қабылданған бір партияға қордың бір жолы ашылады.

```text
suppliers  1 ──< purchases  1 ──< purchase_items  1 ──< medicine_batches  1 ── 1 inventory
branches   1 ──< warehouses 1 ──< inventory       1 ──< sale_items
customers  1 ──< sales      1 ──< sale_items      1 ──< return_items
                 sales      1 ──< payments
                 sales      1 ──< returns         1 ──< return_items

branches   1 ──< branch_assortment >── 1 medicines
```

| Кесте | Не үшін керек |
|---|---|
| `categories` | Препараттарды тауар санаттарына біріктіреді. |
| `manufacturers` | Препарат өндірушілерін сақтайды. |
| `medicines` | SKU, атау, қаптама, өндіруші және рецепт қажеттілігі көрсетілген каталог. |
| `suppliers` | Дәріханаға тауар жеткізетін компаниялар. |
| `branches` | Сатылым мен ассортимент бекітілетін филиалдар. |
| `warehouses` | Әр қойманы өз филиалына байланыстырады. Бір филиалда бірнеше қойма болуы мүмкін. |
| `branch_assortment` | Филиал мен препарат арасындағы M:M байланыс. Әр жұптың ең төменгі қоры және тапсырыс көлемі бар. |
| `purchases` | Жеткізуші, қабылдайтын қойма және сатып алу күні жазылған құжат. |
| `purchase_items` | Сатып алынған препарат, қаптама саны және бірлік бағасы. |
| `medicine_batches` | Сатып алу жолына тиесілі партия, қабылданған саны, түскен күні және соңғы жарамды күні. |
| `inventory` | Қоймадағы нақты партияның ағымдағы қалдығы. |
| `customers` | Клиенттер және олардың адалдық бағдарламасындағы нөмірлері. |
| `prescriptions` | Клиентке белгілі препарат үшін берілген бір реттік рецепт және оның жарамдылық аралығы. |
| `sales` | Чек нөмірі, филиал, сату күні, клиент, мәртебе және сома. Анонимді чекте клиент бос қалады. |
| `sale_items` | Чекке нақты партиядан босатылған қаптама санын, бағасын және қажет болса рецепті байланыстырады. |
| `payments` | Төлем тәсілі, сома, уақыт және әрекет нәтижесі. Бір чекті екі төлеммен жабуға болады. |
| `returns` | Бастапқы чекке қатысты қайтарым құжаты, себебі, күні және ақшалай сомасы. |
| `return_items` | Қайтарылған сату жолы, саны және тауардың әрі қарайғы күйі. |
| `report_settings` | Есептік күнді, жарамдылық терезесін және валютаны бір жерде сақтайды. |

## 🎯 Бизнес-функциялар

- **Партияны қабылдау.** `receive_batch(...)` сатып алынған санды және қабылдау күнін тексереді. Партия мен қойма қалдығы бір транзакцияда құрылады.
- **Рецептпен сату.** `trg_01_prescription_check` препаратты, клиентті және рецепт мерзімін салыстырады. Ішінара бірегей индекс бір рецептті екі рет пайдаланудан қорғайды.
- **Қордан босату.** `trg_02_inventory_deduct` қор жолын құлыптайды. Қойма чек филиалына тиесілі, партия сату күнінде жарамды және саны жеткілікті болса, қалдық азаяды.
- **Чекті жабу.** `open → paid` ауысқанда чек жолдарының сомасы сәтті төлемдермен салыстырылады. Екі бөлікпен төленген чек те бір сатылым ретінде есептеледі.
- **Қайтарым.** Қайтарылған жалпы сан бастапқы жолдағы сатылған санмен шектеледі. `restock` тауарды сол партияға қайта қосады, `write-off` есептен шығаруды тіркейді. Рецептуралық немесе мерзімі өткен тауарды қорға қосуға тыйым салынған.

## 🧪 Тексеру және қорғау

```sh
psql -X -d pharmacy_case -v audits_only=1 -f 05_queries.sql
psql -X -d pharmacy_case -f 05b_negative_tests.sql
psql -X -d pharmacy_case -f 05d_live_window.sql
psql -X -d pharmacy_case -v demo_only=1 -f 05_queries.sql
```

V01–V06 аудиттерінде әрбір `violations` мәні **0** болуы тиіс. T09 үшін екі терминал ашыңыз. Біріншісінде `psql -X -d pharmacy_case -f 05c_t09_a.sql`, артынша екіншісінде `psql -X -d pharmacy_case -f 05c_t09_b.sql` орындаңыз. A сессиясы B сессиясының құлыпты күткенін тексереді, содан кейін екі транзакция да кері қайтарылады.

`demo_only` режимі нақты деректердің көшірмелерімен екі `UPDATE`, бір `DELETE`, екі `ALTER TABLE` және бір `DROP TABLE` орындайды. Соңында негізгі 19 кестенің жол саны мен бақылау сомалары салыстырылып, `ROLLBACK` орындалады.

## 🧠 Қолданылған SQL тақырыптары

- **Құрылым және тұтастық:** `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `CHECK`, `NOT NULL`, `DEFAULT`, құрама кілт, ішінара бірегей индекс.
- **Іріктеу және топтау:** `DISTINCT`, `WHERE`, `BETWEEN`, `IN`, `LIKE`, `ORDER BY`, `LIMIT`, `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `GROUP BY`, `HAVING`.
- **Біріктіру және аналитика:** `INNER JOIN`, `LEFT JOIN`, `RIGHT JOIN`, `FULL OUTER JOIN`, `UNION ALL`, `WITH`, `CASE`, `FILTER`.
- **Транзакциялар:** PL/pgSQL функциялары мен триггерлері, `SELECT … FOR UPDATE`, `BEGIN`, `COMMIT`, `ROLLBACK`.
